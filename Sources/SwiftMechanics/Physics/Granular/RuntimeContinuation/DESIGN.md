# Granular Runtime continuation

## Purpose and Scope
Parent [Granular](../DESIGN.md), no children. Own the AF27 selected EX-004/IM43 accepted Runtime journal and cold continuation domain. This adds genuine particle/history/RNG transaction composition; it does not supply arbitrary history decoding, packing, model migration, cross-build bitwise replay or full EX-004 completion.

## Responsibilities and Boundaries
Existing GranularPreparing and GranularEvolving alone create particle/history/basis records. Their internal initializers are not continuation authority. ReferenceGranularPreparation initializes zero-step histories; ValueGranularCheckpoints is same-owner value replay. No public arbitrary binary history restore exists. This component therefore records a bounded accepted-step journal and reexecutes original public particle physics from an explicitly identified immutable initial seed recipe. Runtime alone publishes accepted trials and rolls rejected trials back. No source producer is changed and no decoded ContactHistory/GranularState is fabricated.

## Architecture
```text
public freshly prepared initial seed + fixed step + ordered explicit gravity choices + original policy
 -> immutable sealed source/signature -> accepted choices/RNG/time journal
 -> public builtin particle reexecution -> actual histories/bases/motions
 -> canonical current step -> supplier comparison/ledger gate
 -> trial contributor + trial RNG + physical time
 -> Runtime whole-checkpoint admission -> accepted publication OR rollback
```

## Contracts and Invariants
GranularRuntimeSource owns the original initial seed, carrier ModelStamp, fixed positive timeStepSeconds, nonempty finite ordered gravityChoices, original GranularPolicy, maximumAcceptedSteps, maximumBytes, maximumMetadataBytes and explicit GranularRuntimePhysicsBudget. Admission requires at least one original contact binding, zero steps/time/initial RNG draws, zero bristle/dissipation/sequence histories and no basis; all source sizes are bounded before traversal/allocation. Source signature includes original identities/revisions, physical sphere/plane/proxy/filter/law parameters, initial motions, seed, step, gravity choice order, original acceptance policy and finite budgets. Fresh source construction from the same public preparation recipe reproduces this signature without retaining the old state/model/source owner. Changed source, policy, gravity choice, initial motion, seed, revision or step fails before replay publication.

Each accepted trial draws exactly once using RuntimeTrial.nextRandom. Choice is the explicitly declared index `draw % gravityChoices.count`; no uniform-distribution claim, silent force choice or default forcing. Journal retains each accepted choice and exact time/steps/Runtime RNG seed/state/draws. Original particle state.random remains the immutable preparation/distribution seed because GranularEvolving does not change it; continuation.random is the actual Runtime RNG. The whole checkpoint must match continuation time bit pattern, acceptedSteps and RuntimeRandomState exactly. Rejection or failed admission publishes neither particles/history nor RNG draws.

GranularRuntimeContinuing declares non-generic initial/encode/decode requirements. GranularRuntimeJournal is the sealed immutable implementation; GranularRuntimeContinuation has internal construction and exposes producer-generated particles, actual Runtime random and gravityChoiceIndices. ReferenceGranularTrialOperator implements GranularRuntimeTrialOperating.advance(model:duration:trial:control:work:). GranularRuntimeContributors and GranularRuntimeCheckpointHandler compose original public Runtime validation; only a fixed single-static-body, fixed-root, zero-coordinate same-stamp/frame carrier is supported. Exactly one declared granular contributor is required. Model migration remains explicit unsupported with an incomplete marker.

Cold decode verifies the canonical source signature, exact length, maximum step count and each RNG-derived choice. It reconstructs all particle motions, ContactHistory, transported ContactBasis and time/steps solely by ReferenceGranularEvolution public calls. Stored metadata is compared to this actual result. Byte records are continuation inputs, not independently allocated constitutive authority. Current trial first executes the canonical original step, providing positive prefixes in all native ledgers; injected GranularEvolving runs afterward. Compare every original motion/history/basis/model/time/steps/random field exactly and adopt the canonical result. Valid supplier failures propagate; native ledger replacement/decreasing counters restore known prefixes on success and failure, with unavailable work marked. No retries or fallback.

## Runtime Flows
Decode accepted contributor under bounded work; verify carrier and physical trial time; require duration bit-pattern equals fixed step and remaining step capacity; draw actual trial RNG; execute canonical and supplier current step; encode immutable next continuation; replace trial contributor and set physical time. Runtime then independently decodes/reexecutes during checkpoint admission and binds complete checkpoint metadata before its publication. Per-step Runtime safe points poll original control through a throwing callback without mutating its ownership.

## State, Ownership, and Lifecycle
Source/journal/continuation are immutable Sendable owners, identical on Native/WASM/Embedded. Work, byte arrays, choices and native GranularWorkspace are exclusive operation-local values. No global cache, raw mutable target branch, unsafe isolation, private producer construction or owner-ticket access. Returned particle state backing is owned by original immutable producer values. Fresh Runtime/contributor/source/model owners retain no previous accepted state or contact workspace.

## Failure, Concurrency, and Constraints
GranularRuntimeError owns invalidInput, unsupportedDomain, staleSource, malformedJournal, capacityExceeded, cancelled, invalidSupplierEvidence, supplierLedgerReplaced and nested GranularError/RuntimeFailure/NumericalError. Failure maps preserve cancellation/resource cause and supplier work availability. Work explicitly bounds visited byte/control units, simultaneously live journal byte storage and all original Numerical/Collision/Contact/supplier budgets. Prior charged prefixes survive rejection and failure. Native physical limits are separate published budgets, not inferred conversions; Runtime validation conservatively precharges their complete operation/iteration/call ceilings before any replay, and reserves a documented logical byte upper bound from native scalar ceilings plus journal backing. This admission quantum is a bound on the whole replay work, not a claim that every admitted operation was performed. Native ledgers separately retain actual counters. Cancel before and throughout metadata, parsing, replay, supplier and publication phases. Checked count arithmetic rejects overflow. No unbounded replay: accepted-step cap is part of source signature.
