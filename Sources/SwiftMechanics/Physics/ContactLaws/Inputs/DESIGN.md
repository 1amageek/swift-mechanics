# Independent framed constitutive inputs
## Purpose and Scope
Parent [module](../DESIGN.md). Owns SI inputs, contact/body/geometry/frame/layout identity and caller budgets. Children: none.
## Responsibilities and Boundaries
No collision type, geometry calculation, impulse or accepted-time lifecycle. Caller supplies separation s (m; positive open), v=vB-vA (m/s), omega=omegaB-omegaA (rad/s), dt>0 (s). Normal points A to B. Result force/couple act on B and their negatives on A at the consumer's contact application locations.

## Architecture
```text
Model references + contact-to-query quaternion -> tangent x/y, normal z in query frame
separation + relative linear/angular velocity + dt -> bounded constitutive input
```
## Contracts and Invariants
ContactIdentity contains nonempty contact key, ordered body references and optional paired body-scoped material-site identities, common frame reference, independent geometry revisions and tangent-layout revision. ContactBasis uses a Core unit quaternion; local x/y define material anisotropy axes and local z the normal. Its frame reference must exactly match input identity. Tangent axes are caller-advected material directions; changing their physical definition requires a layout revision. Scalar input validation rejects nonfinite s, negative/nonfinite start time and nonpositive/nonfinite dt. Input has no independently supplied tangential displacement: the only displacement authority is dt times projected relative velocity, preventing contradictory displacement/velocity inputs. Response acceptance uses caller dimensional energy/power absolute tolerances, a relative term and positive reference energy/power, plus an independent dimensionless cone tolerance. Selected backend is reference Float64 CPU, with no fallback.
## State, Ownership, and Lifecycle
All records immutable Sendable. ContactWork is a caller-owned value passed inout; no reference/global storage. History components follow the advected tangent axes, preserving elastic energy under rigid rotation; this is not an automatic rolling/slip transport algorithm.
## Failure, Concurrency, and Constraints
Budget has nonnegative operation-quanta/scalar-slot/output-record limits. Each operation charges metadata UTF8 scans (two quanta per byte, using borrowed UTF8 views) before identity comparisons; input construction owns its own metadata validation. No unconstrained successful equality scan is hidden behind the fixed scalar charge. Each operation also preflights fixed conservative scalar bounds (pairing 512 operations/128 slots/1 record; initial history 32/96/1; response 4096/256/1; impact 128/64/1), and checks cancellation before work and before return. Quanta count an upper bound on scalar arithmetic/comparisons and fixed record validation, not wall-clock latency. Borrowed inputs are not copied into arrays; no explicit per-evaluation workspace arrays/buffers. Compiler and standard-library allocation behavior is not measured; scalar-slot budgets cover component-owned workspace, excluding caller-owned immutable metadata buffers. Arithmetic overflow propagates typed failure; failed operations return no partial response.

### Material-site identity extension
ContactMaterialSite owns a nonempty material feature key and its caller-owned topology/layout revision. ContactIdentity accepts either no sites for legacy distinct bodies, or an ordered pair of sites. Same-body contact requires exactly matching body references and different material-site keys; changing revision alone cannot create a second physical site. A partial pair or same physical site is invalidIdentity. All records remain immutable Sendable on every target. Geometry/frame/material-site/layout identities participate in history equality, so swapping sites or changing site revision rejects existing history. Consumers own feature eligibility and material coordinates; the constitutive law does not infer geometry or fabricate different body IDs.

Each optional site key is charged by the existing bounded borrowed UTF8 accounting before history comparison. Initial history reserves 32 additional scalar slots for a material-site pair; response reserves 32 for each input/accepted pair. Legacy nil-site inputs retain their exact previous operation/storage budgets. Corresponding actual constitutive/replay/stale/long-key/resource evidence passed in five new Native cases alongside the fourteen original law cases. RigidContactResponse rejects explicit material-site representation; its rigid generalized mass is not a nodal mass. This extension does not itself qualify deforming surface collision or evolution.

The initial flat optional-site extension caused the original ordinary WASM public probe to cross its 128 KiB stack boundary in nested rigid witness preparation (private immediate guard, not the misleading later release trap). Ordered sites therefore share one immutable ContactMaterialSitePair owner retained by the ContactIdentity value. Its two immutable sites never mutate; copying contact/history values retains the owner instead of replicating two optional string/revision records. Public site access and structural equality remain value-semantic. The owner exists on all targets with identical Sendable/lifetime and no lock/cache/unsafe exception. Fixed slot charges remain conservative; this is a causal lifetime correction, not an allocation or throughput performance claim. Final original-profile Native, ordinary WASM and Embedded public probes exited 0 after the owner correction. The private immediate ordinary-WASM stack-boundary guard also exited 0; its modified artifact is diagnostic only, not qualified execution.
