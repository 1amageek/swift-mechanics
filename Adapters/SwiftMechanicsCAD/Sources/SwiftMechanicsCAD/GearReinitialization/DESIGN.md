# Gear reinitialization

## Purpose and Scope
Parent [SwiftMechanicsCAD module](../DESIGN.md); no production children. Own the selected CA-009 edit-to-Runtime reinitialization transaction for two admitted ideal external spur gears on spatial, fixed-root, dynamic scalar revolute shafts. Re-evaluate the edited CAD source, compile a new mechanics revision, bind the new shafts, validate original constrained physics and explicitly reset numerical continuation before atomic publication. This is a Native companion-adapter contract; exact CAD moments, proxy/FEM generation and compatible physical-state migration remain outside this selected successful domain.

## Responsibilities and Boundaries
The caller supplies an explicit fresh MechanicalDescriptor, occurrence/body/frame placements and material, supplied inertias, initial q/v/a, mounting phases, drive and numerical policies. The descriptor is a recipe, not a compiled authority. This owner runs the original compiler and gear binder itself. GeometryAdmission alone issues original exact CAD geometry; GearBindings alone issues the selected source/shaft/network association. NonlinearMechanismEquation and its strict checkpoint handler alone validate original retained rows, complete force and physical acceleration. RuntimeSession alone compares the complete source checkpoint under its operation lease and publishes the target atomically. No supplier implementation or internal token is consumed or modified.

## Architecture
```text
edited CADDocument + explicit fresh descriptor and policies
 -> original exact CAD admission -> original ReferenceMechanicalCompiler
 -> actual makeState -> original gear binder -> retained network.equations
 -> sourceBoundModel nonlinear equation + integration provider
 -> required CAD recipe validator + original strict cold handler
 -> issuer-owned immutable prepared reinitialization
 -> actual RuntimeModelReplacing.replaceModel
 -> exact source lease comparison / target admission / atomic publication
 -> saved checkpoint -> newly rebuilt final context -> fresh owner restart
```

## Contracts and Invariants
The proposed public interface is CADGearReinitializationPreparing with two non-generic requirements: initialize(document:occurrences:tolerance:limits:recipe:runtime:time:work:transmissionWork:) throws(CADGearReinitializationError) -> CADGearRuntimeContext, and prepare(source:expectedSource:document:occurrences:tolerance:limits:recipe:choice:work:transmissionWork:) throws(CADGearReinitializationError) -> CADPreparedGearReinitialization. ReferenceCADGearReinitializationPreparer supplies the actual builtin pipeline. CADGearReinitializationPublishing.publish(_:in:) throws(CADGearReinitializationError) -> RuntimeAcceptedState delegates to the original RuntimeModelReplacing requirement; its fixed implementation exposes no unchecked replacement constructor.

The recipe parameter is any CADGearRuntimeRecipeBuilding. Its required makeRecipe(geometry:time:) throws(CADGearReinitializationError) -> CADGearRuntimeRecipe receives the actually re-admitted immutable geometry and the explicit initial time or exact accepted source time. The caller resolves fresh anchors through that public geometry owner and supplies mechanics data afterward. The preparer invokes this supplier exactly once, then itself compiles and validates its returned descriptor. This avoids inventing future anchor signatures or re-evaluating CAD merely to build an input request. The builder does not issue compiled or accepted authority; unknown builder cost/failure remains explicit supplier work.

CADGearRuntimeRecipe carries the uncompiled MechanicalDescriptor, CompilationPolicy, coordinate layout, CADGearPairRequest and binding/transmission policies, equation identity/drive/solve/projection/DynamicsAdmission policies, ExplicitIntegrationPolicy and bounded identity/physical-validation limits. CADGearRuntimePolicy carries caller capacity, continuation identity, determinism, workload, seed and bounded recipe/metadata storage. Required schemas are derived from the actual prepared CAD and integration providers; arbitrary caller catalogs are not admitted in this selected domain. There are exactly three spatial bodies and two root-mounted dynamic revolute-Z shafts, no extensions, prescribed anchors, external loads or additional law records. Supplied inertia provenance stays supplied; an exact-CAD-moments request retains the existing typed refusal.

CADGearRuntimeContext retains the sealed original gear binding, actual compiled model, source-bound nonlinear equation, integration provider, immutable required CAD recipe contributor, derived configuration, strict contextual handler and sequence-zero initial records. Its constructor accepts only an opaque immutable admission token with an explicit fileprivate initializer in the actual pipeline issuer file. Initial context issuance includes actual cold admission of the complete initial physical state, not merely kinematic makeState or a descriptor signature check. The caller may create a real RuntimeSession from these public admitted context fields; creating a session remains original Runtime authority.

The retained transmission network already publishes QuadraticConstraintSystem through network.equations. The target equation consumes that exact value, its actual layout, caller drive and supplied inertias through the original sourceBoundModel initializer. No row conversion, ideal-ratio substitution, separate force algorithm or fabricated RuntimeStepControl is necessary. Full target a is explicitly supplied by the fresh physical recipe and must pass original constrained-force cold admission; incorrect a is refused rather than replaced silently.

Preparation first validates the old context's complete expected checkpoint through its actual strict handler and CAD required record. It then re-admits the edited document, requires the same document/model identities with an actual changed CAD source identity and strictly newer mechanics revision, compiles the explicit fresh descriptor, and invokes the original fresh gear binding. Target physical time must equal the accepted source time bit for bit. The recipe's q/v/a is the caller's explicit reinitialization choice, with the original network phase/speed and physical equation accepting it. Occurrence IDs, body/frame IDs and shaft IDs remain explicit and unique. Changed centers/placements/anchors must be present in the caller recipe and accepted by the new original CAD queries and actual compiled tree; old witnesses never silently rebind.

CADGearReinitializationChoice has reinitialize and preserveCompatibleState. Only reinitialize succeeds. The callable preserveCompatibleState branch must carry INCOMPLETE_IMPLEMENTATION and return a dedicated unsupportedMigration failure before any prepared result or publication. No physical compatibility, law migration or geometry-resolution success is inferred from unchanged IDs or ratios.

The bounded required CAD recipe record binds the complete admitted CADSourceIdentity, both occurrence identities/placements/material-density declarations, resolved gear parameters and selected original end-face identity/frame, shaft/phase/fidelity association, actual compiled-model association, declared initial time/q/v/a bits and source-bound equation descriptor. Its validator retains the actual immutable binding and exact model descriptor and refuses a different source, model, recipe, payload, schema or unexpected catalog. Payload bytes use an explicit versioned owned encoding with deterministic field order and exact scalar bits, bounded before growth; trailing, malformed, shortened or changed bytes fail. The record is provenance admission, not a new CAD geometry issuer or a force certificate. Original physical authority remains the strict nonlinear handler.

The selected complete source and target catalogs consist of the CAD recipe record and actual integration record, each once. No additional actuator/contact/sleep/hybrid history is discarded or reset. A source with extra, missing, duplicate or unknown records fails. Target integration history is explicitly rebuilt using provider.record at target q/v/time, nextStep = caller initialStep, normalizedError = nil for classicalRK4, and acceptedSteps = source acceptedSteps + 1. This selects classicalRK4 so numerical reset has an unambiguous original error contract. The CAD record is regenerated from the new original binding; neither source record's bytes are reused as target continuation.

The prepared result retains source context, the complete expectedSource, admitted target context/physical/contributors and the original RuntimeModelReplacement request privately. Its raw constructor is sealed to the preparation issuer. Preparation cold-admits the actual target checkpoint with preserved source RNG and checked sequence +1. Publication repeats original target admission under the actual Runtime lease, compares the complete expected source, and retains original capacity/continuation/determinism gates. Preparation and publication do not draw RNG. A stale source, cancellation, failed target force or failed registry cannot publish a partial state.

Fresh final-context reconstruction uses the original final CAD document and fresh descriptor through the same original admission/compiler/binder pipeline, not retained previous state/model owners. A new real RuntimeSession begins from that final context's sequence-zero initial records. Original restart then decodes the saved final checkpoint and strictly validates final CAD recipe, physical force, exact q/v/time, integration global sequence and RNG before acceptance. This does not introduce a mutable bootstrap flag or accept source-revision bytes on a target owner.

## Runtime Flows
initialize builds and cold-admits one independent initial context. prepare validates complete source, checks explicit choice, builds one independent target context, emits target reset history and cold-admits its full target checkpoint, then issues a token. publish calls original replaceModel once. Saved restart builds a new final context, creates an original owner, then invokes original restart once. All failures propagate with typed nested supplier failure; there is no retry or fallback.

## State, Ownership, and Lifecycle
Contexts, providers and prepared results retain immutable Sendable owners; no global registry, cache, mutable initialized flag, raw snapshot or unchecked Sendable is introduced. Work is exclusive inout and never reset on failure. Public result constructors receive only issuer-file private tokens. Caller owns RuntimeSession lifecycle; all live session mutation and release/callback rules remain with its original Mutex owner across the supported supplier implementations.

## Failure, Concurrency, and Constraints
CADGearReinitializationError distinguishes unsupported migration/domain/catalog, stale source/model, incompatible time/recipe, capacity/cancellation and nested CAD, compilation, gear binding, mechanism and Runtime failures. Preparation bounds only its own recipe bytes, metadata and fixed records; original CAD supplier work remains opaque and is never reported as zero or a guaranteed bound. Original numerical work and cancellation prefixes remain irreversible. Runtime failure retains the complete accepted checkpoint and RNG. The existential publication API needs only existing RuntimeModelReplacing requirements and never casts to a concrete session or accesses an unavailable configuration property.
